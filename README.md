# Forma

Forma — личный трекер прогресса в игровом формате. Идея проекта: привычки, квесты, стрики, прогресс и позже 3D-персонаж, который визуально отражает развитие пользователя.

## Быстрый старт

```bash
pnpm install
pnpm dev
```

Полезные команды:

```bash
pnpm lint
pnpm build
```

## Архитектура

Проект держится на простой модульной структуре. Не тащим тяжелый DDD/FSD на старте: пишем фичи понятно, а усложняем только когда появляется реальная необходимость.

```txt
src/
├── app/          # Next.js routes/layouts. Тонкий слой маршрутов.
├── core/         # Глобальная инфраструктура: utils, api, env/config.
├── shared/       # Общие UI, хуки и конфиги без бизнес-логики.
├── modules/      # Продуктовые блоки и фичи.
└── canvas/       # Three.js / React Three Fiber, когда вернем 3D.
```

## Слои

`src/app` — только маршруты Next.js, layout'ы и композиция страниц. Страница должна импортировать готовый модуль/экран и не хранить внутри бизнес-логику.

`src/shared` — общие кирпичи проекта: `Button`, `Card`, базовый `Calendar`, общие хуки, конфиг навигации. Важно: `shared` не должен знать про habits, quests, dashboard и другие продуктовые модули.

`src/modules` — место для фич и крупных блоков. Модуль может иметь свои компоненты, хуки, сервисы и типы:

```txt
src/modules/habits/
├── components/
├── useHabits.ts
├── habitsService.ts
└── types.ts
```

`src/core` — техническая база проекта: `cn`, API-клиенты, env helpers, глобальные конфиги. Тут нет React-компонентов и бизнес-смысла.

`src/canvas` — отдельный слой для 3D. Canvas-код не смешиваем с DOM-версткой.

## Текущие модули

```txt
src/modules/dashboard/   # Главный экран и интеграция блоков.
src/modules/habits/      # Привычки и календарь привычек.
src/modules/layout/      # Header, Sidebar, app shell.
src/modules/quests/      # Квесты и связанные компоненты.
```

## Правила разработки

- Общий UI кладем в `src/shared/ui`.
- UI конкретной фичи кладем в `src/modules/[module]/components`.
- Состояние и обработчики фичи выносим в `use[Module].ts`, если компонент начинает пухнуть.
- API/localStorage выносим в `[module]Service.ts`.
- `app/page.tsx` и route-файлы должны оставаться тонкими.
- Tailwind v4 — основной способ стилизации.
- Если JSX набирает слишком много классов, выносим строки классов в `const`.
- Не используем `any`; если тип неизвестен, лучше `unknown` или нормальный тип.

## Shadcn

Shadcn настроен на генерацию UI в `src/shared/ui`.

Базовый импорт:

```ts
import { Button } from '@/shared/ui/button'
```

## Памятка

Если хочется добавить новую фичу, сначала спроси себя:

1. Это общий UI? Тогда `shared/ui`.
2. Это продуктовый блок? Тогда `modules/[name]`.
3. Это техническая инфраструктура? Тогда `core`.
4. Это Next route/layout? Тогда `app`.
5. Это 3D/R3F? Тогда `canvas`.
